# Corridor 2.0 — design contract

Status: in progress, 2026-10-02. This document is the contract every work
package builds against. Where it and the code disagree, fix one of them in the
same change.

It implements the development directive of 2026-10-02 (Sanjiban's 09/15 notes
plus the review that followed), in the order the directive gives: freeze and
reproduce, then the requested application changes, then research. Items that
cannot be done honestly with the data that exists are listed under
*Deliberately not done* with the reason, never quietly skipped.

## 0. Facts established before any code changed

- **The shipped tree is committed** (`shipped-1.3.0`, local tag). The GitHub
  tags `v1.2.0` and `v1.3.0` both point at the 1.1.0 code (`39437e2`).
- **A frozen v1.3.0 baseline** of every sample movie is in
  `build/baseline_v1.3.0/` (commit `eebd6bd`, CLI defaults). Every behavioural
  difference in 2.0 is attributed against it.
- **The labelled stills are not contiguous frames.** Each still's ImageJ label
  records its source movie and time index (`t:N/M`, series, `finterval`).
  Two groups are out of time order in filename order (KK1 `041824_1-12`:
  t44, 67, 23, 1, 45, …; KK2 `052924`, `_1-14`: t14, 15, 29, 6, …), and the
  KK2 group behind the 0.942 ceiling jumps t29 → t48 (6.3 h). The label-
  completeness ceilings and the corrected reference were derived by filename
  adjacency and must be re-derived on true time order (§9).
- **KK1 and KK2 are different instruments**: 0.639 µm/px 12-bit (DS-Qi1Mc)
  against 0.467 µm/px 16-bit (Flash4.0). Equal widths in pixels are different
  widths in micrometres.
- **There is no tracking ground truth and no 3D data** anywhere in the supplied
  data. Claims about tracking accuracy or 3D accuracy cannot be measured on
  real data yet; they are measured on synthetic data with known answers, and
  said so.

## 1. Versioning (one source)

`src/corridor/_version.py` holds `__version__`. Everything else derives from it:
`app_meta.APP_VERSION`, `pyproject.toml` (setuptools dynamic `attr`),
`packaging/version_info.txt` and the Inno Setup define (both generated by
`scripts/sync_version.py`, which `build_release.py` runs first), `run.json`,
the About dialog and the update check. `tests/test_version.py` fails if any
packaged location disagrees. The release that carries schema v2 is **2.0.0**:
removing the axis columns is a breaking change to the output format.

## 2. One validated model, locked by SHA-256

`src/corridor/assets/model_registry.json` (committed; weights are not) lists
every validated model. `src/corridor/core/model_registry.py`:

```python
@dataclass(frozen=True)
class ModelSpec:
    model_id: str              # "jhu_confined_cp3_combi"
    model_version: str
    architecture: str          # "cellpose3-cyto2-resnet"
    cellpose_version: str      # requirement, e.g. ">=3,<4"
    filename: str              # file name on disk
    sha256: str
    training_dataset_version: str
    dimensions: tuple[str, ...]          # ("2D",)
    pixel_size_range_um: tuple[float, float] | None
    validated_app_version: str
    notes: str = ""

class ModelUnavailable(RuntimeError): ...

@dataclass(frozen=True)
class ResolvedModel:
    spec: ModelSpec
    path: Path
    sha256: str
    developer_override: bool = False

def load_registry(path: Path | None = None) -> list[ModelSpec]
def production_spec(dimensionality: str = "2D") -> ModelSpec   # raises ModelUnavailable
def candidate_paths(spec: ModelSpec) -> list[Path]
def resolve_model(dimensionality: str = "2D") -> ResolvedModel  # hashes; raises ModelUnavailable
def research_model(path: Path, *, label: str) -> ResolvedModel  # explicit, developer_override=True
def sha256_file(path: Path) -> str
```

Rules:
- Production resolves exactly one model per dimensionality, verifies the hash
  **before** loading, and raises `ModelUnavailable` with the text *"The
  validated Corridor segmentation model is missing or does not match the
  expected checksum."* plus the path(s) tried. No fallback to `cyto3`, `cpsam`
  or any other model, ever. `CellposeModel(model_type=...)` and bare model
  names are never passed to Cellpose; only a verified absolute path.
- Search order: frozen bundle `assets/models/`, then
  `%LOCALAPPDATA%/Corridor/models/` (the future model-pack location), then the
  source checkout's data tree.
- The only override is for developers: `CORRIDOR_DEVELOPER=1` **and**
  `CORRIDOR_DEVELOPER_MODEL=<path>`. It is recorded in `run.json`
  (`model.developer_override: true`) and raises a critical QC issue, so a
  result produced that way can never pass for a validated one. `CORRIDOR_MODEL`
  is removed.
- The registry has no 3D-validated model. A 3D stack is therefore refused for
  segmentation with a clear message; 3D *measurement and tracking* still work
  on imported label images (§4).
- Removed from the production UI and CLI: the model picker, *Change model*,
  the Settings model path, `--model`, `--builtin-model`, companion-model
  discovery and the two ensemble rungs that used other models (`models`,
  `max_recall`). The threshold rungs (`thresholds`, `wide`) use the same
  validated model and stay, off by default. Legacy configs naming removed rungs
  load as `off`, with a note.
- `run.json["model"]`: `model_id, model_version, architecture, sha256,
  cellpose_version, training_dataset_version, developer_override`.

## 3. Configuration (v2)

Rule for the transition: new fields are **added** first; legacy fields are
removed only once nothing reads them. `RunConfig.from_dict` keeps ignoring
unknown keys, so every saved project and `default_config` still loads.

- `Scale` gains `z_step_um: float | None`, `calibrated_z: bool`,
  `frames_to_hr`, and `anisotropy` (`z_step_um / pixel_size_um`, or None).
  Z spacing is never assumed equal to XY.
- `GeometryConfig(detect_walls=True, min_channel_pitch_um=18.0,
  min_channel_pitch_px=38.0)` replaces `ConfinementConfig`. A legacy
  `confinement` block maps `detect_walls` and the pitches; `mode` and
  `angle_deg` are dropped (there is no axis to configure).
- `TrackingConfig` v2 (axis-free; §5): `max_speed_um_per_min`,
  `area_ratio_min/max`, `position_sigma_um`, `shape_position_fraction`,
  `width_position_fraction`, `velocity_sigma_um_per_min`,
  `initial_speed_sigma_um_per_min` (None = max_speed/3), `sigma_ln_area`,
  `w_shape`, `w_orientation`, `orientation_min_eccentricity`, `w_reversal`,
  `direction_noise_floor_um`, `w_overlap`, `gap_penalty_chi2`,
  `unmatched_chi2`, `max_gap`, `min_observations`, `global_gap_closing`,
  `channel_constraint` (`"auto"` | `"off"`). `gate_chi2` is **derived**
  (`2 * unmatched_chi2`), so the 2U == gate invariant can no longer drift
  (the GUI ratchet and the CLI that ignored it both go).
- `MeasurementConfig(reference_point_px=None, msd_min_pairs=3,
  msd_min_lags_for_fit=3, msd_max_lag_fraction=0.5)`.
- `ImportConfig(axes=None, channel_index=0, labels_path=None)`: an explicit
  axis order when metadata cannot establish it, the channel to analyse in a
  multichannel file, and an optional label image to use instead of
  segmenting.
- New projects do **not** inherit calibration or model keys from
  `default_config` (KK1 and KK2 are 0.639 and 0.467 µm/px; a silent carry-over
  is a wrong answer).

## 4. Dimensionality and import

Canonical internal orders: `YX`, `TYX`, `ZYX`, `TZYX`; a `C` axis is reduced
to `ImportConfig.channel_index` and recorded. T and Z are taken only from
metadata that establishes them (ImageJ `frames`/`slices`, OME `SizeT`/`SizeZ`,
explicit axes strings). Ambiguous data raises `AmbiguousAxes` naming the
choices; the UI asks, the CLI takes `--axes`. A file that says `Z` is never
read as time again.

Calibration carries `pixel_size_um` (XY, square; unequal X/Y is a critical QC
issue), `z_step_um` and `frame_interval_min`, each with its source. Without a
Z step, voxel counts are reported and every µm³/µm² column is empty.

3D detections (`extract_detections_3d`): centroid (x, y, z), `volume_vox`,
`volume_um3`, `surface_area_um2` from a marching-cubes mesh with the real
voxel spacing, principal-axis lengths, elongation, flatness, sphericity,
solidity (convex hull), 3D bbox, mean intensity. Volume cannot be measured
from a 2D movie and is never estimated from one.

## 5. Axis-free tracking

Positions are tracked in isotropic pixel units: `(x, y)` in 2D and
`(x, y, z * anisotropy)` in 3D. Nothing anywhere receives a migration
direction.

**Stage 1, frame to frame.** Each track carries a constant-velocity Kalman
state `[r, v]` with covariance `P`. Prediction over `dt` frames uses
`F = [[I, dt I], [0, I]]` and continuous white-noise-acceleration process
noise, discretised exactly: per axis `Q(dt) = q [[dt^3/3, dt^2/2], [dt^2/2,
dt]]`, so the predicted position widens like `dt^3` over a gap.

The process noise is defined **per minute, not per frame**:
`velocity_sigma_um_per_min` is `sqrt(q)` in µm/min per √min (default 0.1, the
along-body 0.093 measured on the v1.3.0 baseline rounded up; 0.45 µm/min of
velocity change over one 20 min frame, 0.32 over a 10 min one).
`TrackingConfig.process_noise_px(scale, dt)` is the one place `Q` is computed
from the config and the frame interval (`q * frame_min^3 / pixel_size^2` in
px²/frame³); the tracker binds it once per run and never reads the field
itself, so the same cells imaged every 5 or 20 min get the same velocity
diffusion per hour. Uncalibrated, the value is read in px and frames.

`Q` and the fresh-track prior are **isotropic**: the same `Q` on every axis,
and a fresh track starts with zero velocity and speed variance
`(initial_speed)^2 I`. A body-shaped `Q` (across-body acceleration scaled by
the body's aspect) was tried and withdrawn: the across/along ratio it rests on
was measured in channels whose walls stop sideways motion, and in an open
field it split elongated cells that turn. It remains an opt-in for confined
fields (`body_shaped_noise_in_lanes`, `Q_axis ⊗ (u u^T + (minor/major)^2 n
n^T)`), applied only where the lane gate applies, and is reported as a control
run in `docs/tracking_v2_vs_v1_baseline.json`.

Measurement noise is shaped by **each cell's own body**, not by an axis:
`R = position_sigma^2 I + (shape_position_fraction * major)^2 u u^T +
(width_position_fraction * minor)^2 n n^T`, with `u, n` the detection's major
and minor directions. A long, thin confined cell has an uncertain centroid
along its length and a precise one across it, which is exactly the physical
reason the old along/across model worked, now derived locally per cell. Once
a track has moved, `P` itself becomes elongated along its learned motion.

Pair cost, in chi-square units (`CostBreakdown` reports every term):

```
motion      = d^2 = (z - H x_pred)^T S^-1 (z - H x_pred),  S = H P H^T + R
size        = (ln(size_j / size_i) / sigma_ln_area)^2             # area or volume
shape       = w_shape * [(Δ ln aspect / 0.35)^2 + (Δ solidity / 0.10)^2]
orientation = w_orientation * (1 - |cos angle between major axes|)   # ecc >= 0.6
direction   = w_reversal * (1 - cos(step, velocity)) / 2           # moving tracks
overlap     = w_overlap * (1 - IoU(previous mask shifted by prediction, candidate))
gap         = gap_penalty_chi2 * (dt - 1)
total       = sum; gated if any hard gate fails or total > gate_chi2 (= 2U)
```

Hard gates: gap (`dt > max_gap + 1`), physical speed (`max_speed_um_per_min`),
size ratio, the motion gate (`d^2` above the chi-square 0.999 quantile for the
dimension), and the optional lane gate. Assignment keeps the block LAP with
unmatched cost `U`; a pairing at `FORBIDDEN` is never selected.

**Link margins.** Every accepted link carries two margins, in chi-square
units; they are margins, not probabilities, and are named as such until they
are calibrated.

- `link_margin` (exported as `link_margin_chi2`) = (cost of the next-best
  explanation for either the track or the detection, capped at `2U`) minus
  the chosen cost. Small means ambiguous; negative means the global optimum
  gave the track a detection another track explains more cheaply (locally
  contested), and it is reported as is, not clamped.
- `link_margin_global` = how much the frame's optimal total rises when the
  assignment is **re-solved with that link forbidden**, knock-on effects
  included. Only the link's connected group of tracks and detections is
  re-solved (the block problem separates exactly by group). Never negative;
  0 is a tie. It measures how much the solution depends on the link, not how
  contested the link is, so an ambiguity rule reads `link_margin`.

**Stage 2, global gap closing.** After stage 1, every track end is matched
against every later track start within `max_gap + 1` frames in one global
assignment (switch: `global_gap_closing`). The motion evidence comes from both
sides: the end's state predicted forward to the start (`d2_f`), and the later
track Kalman-filtered backwards over its own observations and predicted back
to the end (`d2_b`). A side counts only if its track has at least two
observations (a one-observation track's "prediction" is the fresh prior and
would dilute the informative side). With both sides the motion gate is on the
joint statistic `d2_f + d2_b` against the chi-square 0.999 quantile for
`2 * ndim` degrees of freedom (18.5 in 2D, 22.5 in 3D) and the motion term is
`(d2_f + d2_b) / 2`, on the stage-1 per-`ndim` scale so the same `U` and cost
gate apply; with one side, that side's `d^2` against the stage-1 gate. The
other terms (size, shape, orientation, direction, overlap, gap) are the
stage-1 terms across the gap, and both margins are computed on the stage-2
assignment. Closures are flagged `gap_closed` and recorded in
`tracking_events.csv`. This is the temporal (multi-frame) association step: a
link is judged on the trajectories either side of the gap, not on one frame.

On the five baseline movies (detections rebuilt from `build/baseline_v1.3.0`,
`scripts/compare_tracking_to_baseline.py`), the default tracker agrees with
v1.3.0 on 0.929 of 155 observations (0.942 with the body-shaped opt-in, 0.993
with v1's duplicate recoveries removed), makes 0 lane crossings in the wide
fields, and every link where the two differ is reviewed in
`docs/tracking_v2_vs_v1_baseline.json`.

**Lanes instead of an axis.** `core/geometry.py` keeps the wall-ridge detector
but returns `ChannelGeometry(lanes, source, confidence, pitch_px, notes,
applied)`. Each lane has its own centre line and half-width; there is no
shared direction. With `channel_constraint="auto"` the lane gate is applied
only when lanes were detected from walls, and `run.json` says whether it was.
`confinement.py` becomes a deprecated reader for v1 manifests only.

**Events and flags.** These survive: `merge_suspected` (no fabricated
centroid), dormancy and the `dt <= max_gap + 1` rule, and the unlinked-start
audit (now reporting `dx, dy, [dz], distance, mahalanobis`). These are new:
`split_suspected`, `enters_at_border` and `exits_at_border`, `gap_closed` and
`FrameEvent.notes` (now populated). Track ids are renumbered by first
appearance after gap closing, and recovery provenance is keyed to the final
ids.

## 6. Measurements (MTrackJ-equivalent and beyond)

One canonical physical velocity per step: `v = Δr_um / Δt_min`, where `Δt` is
the elapsed time between observations, so gaps are handled correctly. Every
per-hour value derives from it (`× 60`) and is never recomputed from
geometry.

Per observation (`tracks.csv` v2), following MTrackJ's conventions:
- `cumulative_path_um` (Len) and `distance_from_start_um` (D2S) are 0 at the
  first point.
- `distance_from_previous_um` (D2P) and speed are empty at the first point.
- `distance_from_reference_um` (D2R) is filled only when a reference point was
  set.
- Also per observation: `speed_um_per_hr`, `vx/vy/vz_um_per_hr`,
  `acceleration_um_per_hr2`, `turning_angle_deg`, the morphology columns, and
  `link_margin_chi2`. The µm/min columns stay for continuity.

`track_msd.csv`: `track_id, lag_frames, lag_time_min, lag_time_hr, n_pairs,
msd_um2` (and `msd_px2`). The lag is the **actual** frame difference between
every pair of observations, so a track seen at frames 1, 2, 5 contributes lags
1, 3 and 4, not 1, 2 and 3. MSD is in µm², never µm. `msd_alpha` is fitted
(log-log OLS, with r² reported) only over lags with at least
`msd_min_pairs` pairs and at most `msd_max_lag_fraction` of the span, and only
when at least `msd_min_lags_for_fit` such lags exist. Otherwise it is empty.
Persistence is reported as directional autocorrelation. A persistent-random-
walk time is reported only with its fit quality, and an optimiser converging
is not evidence that the model is right.

`track_summary.csv` v2 follows directive §20, plus the existing robust net and
path speeds in both units.

## 7. Output schema v2

`run.json` gains `"schema_version": 2`, `model`, `channel_geometry` (replacing
`confinement`), `measurement`, `input.axes`, `input.shape` and
`dimensionality`. The files written are `tracks.csv`, `track_summary.csv`,
`track_msd.csv`, `detections.csv`, `tracking_events.csv`, `qc_issues.csv`,
`recovery_attempts.csv`, `unlinked_starts.csv`, `segmentation_diagnostics.csv`,
`masks.npz` (`T[Z]YX`), and `run.json` (last). These columns are gone from v2:
`v_along*`, `v_across*`, `net_along_um`, `net_across_um`,
`along_speed_um_per_min`, `along_channel_px` and `across_channel_px`.

**Loading.** `store/project.py` reads both schemas. A v1 run (no
`schema_version`) is upgraded in memory: per-hour units, Len/D2S/D2P and MSD
are derived from its positions; it is never re-segmented; its legacy channel
lines are drawn as lanes. There are fixtures for 1.0.0, 1.1.0 and 1.2.0/1.3.0
outputs, and for the database's `config_json`/`manifest_json` copies.

**Exports.**
- Per track: *Selected track CSV/XLSX* (XLSX written without a new dependency).
- Whole analysis: *All tracks CSV*, *All track summaries CSV*, *MSD curves
  CSV*, and *Full analysis bundle*, which now includes `recovery_attempts.csv`
  and `track_msd.csv`.
- CSV remains canonical.

## 8. Quality control v2

Removed: `weak_axis` and `lateral_drift`. `multichannel_field` and
`inferred_channel` become lane notes.

Added:
- `link_ambiguous`: low `link_margin`.
- `morphology_discontinuity`.
- `size_jump`: area/volume.
- `long_reacquisition`.
- `gap_dominated_track`.
- `split_suspected`.
- `border_entry` / `border_exit`.
- `count_jump`: object count changes abruptly between frames.
- `likely_missed_detection`: a track is consistent across a one-frame gap, so
  that frame is a review case.
- `developer_model_override`.
- `no_z_step`.
- `anisotropic_pixels`.
- `imported_segmentation`.

Every issue carries a frame and track so it stays clickable.

## 9. Research (outside the application)

`training/` holds everything that trains or evaluates; nothing in
`src/corridor` imports it, and the installer never contains it.

- `datasets.py` builds a **dataset registry** from the ImageJ metadata of every
  still. Each record has experiment (date + series), true time index, pixel
  size, frame interval, camera bit depth, instances, sha256 and split.
- `splits.py` splits at experiment level. The test set is frozen first; frames
  of one experiment never straddle splits.
- `augmentations.py` holds recorded, orientation-free, training-only
  augmentations:
  - Poisson and Gaussian noise, gain/offset, gamma, contrast.
  - Defocus and anisotropic blur, downsample-and-reinterpolate, scale.
  - Flips and 90° rotations.
  - Illumination gradient and vignetting.

  The old `(1, 41)` background filter ran across channels by accident and is
  replaced.
- `evaluate_segmentation.py` scores with `core.metrics` only. It reports:
  - AP over IoU 0.5–0.95, precision/recall/F1, FP and FN per image, splits and
    merges.
  - Breakdowns by experiment, contrast quartile, size and border distance.
  - Optional border-margin exclusion and boundary refinement, each reported
    beside the unmodified figure.
  - Results against the corrected reference first, with the original beside it
    and the undrawn-cell count stated.
- `hard_examples.py` ranks unlabelled frames for annotation (zero detections
  between occupied frames, count jumps, broken or oversized masks, low temporal
  consistency).
- **The corrected reference and the label-completeness ceilings are rebuilt on
  true time order** (`build/corrected_reference_v2/`). The time-based rule
  interpolates by elapsed time and refuses brackets that are too far apart in
  time. The old figures stay in the history with the reason they were
  withdrawn.
- **Cellpose-SAM.** Experiment B (`cpsam_v2` zero-shot) runs on the same
  held-out images in a separate `.venv-cp4`. Experiment C (fine-tuning) has a
  working, smoke-tested pipeline; whether a full CPU run is feasible is
  measured, not assumed.
- **Morphology → future migration** (`training/predict/`):
  - Strict-morphology features: the mask only, with no position, velocity or
    history.
  - Experiment-level splits, the mandatory baselines, and calibrated intervals.
  - It is validated first on synthetic data with a planted signal (it must
    find it) and a null (it must not). Then it is run on the real tracks and
    reported whatever the result.

## 10. Deliberately not done, and why

- **Modifying the Cellpose-SAM architecture (MorphoMotion head, adapters).**
  The directive itself orders this after a fine-tuned baseline exists, and
  there is not yet one to beat.
- **A full Cellpose-SAM fine-tune**, unless a CPU run is measured to be
  feasible on this machine (§9).
- **Validating 3D segmentation.** There is no 3D ground truth. 3D measurement
  and tracking are validated on synthetic volumes with known answers.
- **A tracking-accuracy number on real data.** There is no ground truth. A
  manual-annotation protocol and the scoring code ship instead, so the first
  annotated movie produces the number.
